# 运行 OpenClaw 而不烧钱、不消耗配额或失去理智

## 快速总结

OpenClaw 很有用，但大多数人遇到的痛点来自于让一个模型做所有事、盲目跟风或在不需要的地方运行昂贵模型。

对我有效的做法是把 OpenClaw 当作基础设施而不是聊天机器人。保持一个便宜的模型作为协调器 (Coordinator)，使用代理 (Agent) 做真正的工作，明确指定路由，让内存和任务状态可见。便宜的模型能很好地处理后台工作。强大的模型在你有意地调用它们而不是默认使用它们时最有力。

你不需要昂贵的硬件，也不需要部署巨大的本地模型就能从中获得价值。从小处开始，在让它持续运行之前先确保稳定，避免跟风炒作。如果有什么地方感觉不对，先查阅官方文档和 Issue。OpenClaw 更新频率很快，有时候真的就是一个 Bug。

如果你想要炫目的演示和带着震惊表情的 YouTube 缩略图，这个可能不是你要的。下面介绍的是真实的日常使用场景。

---

我一直看到相同的 OpenClaw 相关问题。人们问为什么感觉慢，为什么总是在规划而不是执行，为什么忘记了东西，或为什么免费层突然消失了。反复回答同样的问题后，写一份指南然后分享链接就更有意义了。

这不是官方指导，我也不隶属于 OpenClaw 或任何模型提供商。这只是我通过运行它、破坏它，然后反复循环超过我想承认的次数所学到的东西。

有一点需要提前说明：OpenClaw 更新很快。有时每天，有时更频繁。当奇怪的事情发生时，不一定是因为你配置错了。有时是回归、Bug 或刚着陆的新功能。

在采纳网络上任何人（包括我）的建议之前，先查阅官方 OpenClaw 资源：

- [https://docs.openclaw.ai/help/faq](https://docs.openclaw.ai/help/faq)
- [https://docs.openclaw.ai/](https://docs.openclaw.ai/)
- [https://github.com/openclaw/openclaw/issues](https://github.com/openclaw/openclaw/issues)
- [https://github.com/openclaw/openclaw/pulls](https://github.com/openclaw/openclaw/pulls)

阅读开放 Issue 和最近的 PR 为我节省了数小时。不止一次我以为自己破坏了什么，结果发现这早就被发现了，而且正在积极处理。

## 大多数人早期犯的错误

最常见的错误是把 OpenClaw 当作一个应该一次处理所有事情的超级智能聊天机器人。对话、规划、研究、编码、内存、任务追踪、监控。都通过一个模型，一直如此。

这种设置最终会导致无尽的后续问题、权限循环、无声故障和消耗的配额。当它有效时，代价很高。当它坏了时，很难理解为什么。

对我来说点醒的是，主模型应该是协调器，而不是工作模型。默认代理应该有能力但不是过度杀伤。昂贵的模型应该远离关键路径。

我的配置大概是这样的：

```json
"agents": {
  "defaults": {
    "model": {
      "primary": "anthropic/claude-sonnet-4-5",
      "fallbacks": [
        "kimi-coding/k2p5",
        "synthetic/hf:zai-org/GLM-4.7",
        "openrouter/google/gemini-3-flash-preview",
        "openrouter/openai/gpt-5-mini",
        "openrouter/openai/gpt-5-nano",
        "openrouter/google/gemini-2.5-flash-lite"
      ]
    }
  }
}
```

确切的模型列表不如意图重要。昂贵的模型不在默认循环中，回退 (Fallback) 行为是明确的。

## 自动模式和盲目路由

我早期尝试过自动模式和盲目路由。后来停止使用两者。

让系统决定使用哪个模型的想法听起来很好。当我真正运行它时，导致了优柔寡断、意外的成本飙升和当问题出现时我无法推理的行为。

明确更好。默认路由保持便宜和可预测。代理固定到特定模型用于特定工作。当运行昂贵的东西时，是因为我要求它。

更少的魔法。远更容易调试。

---

## 为什么强大的模型不应该是默认值

高质量模型如 Opus 是有用的。我使用它们。它们擅长重组提示词 (Prompt)、设计代理、理解复杂问题，以及修复已经破坏的东西。

我被烧伤的地方是让这个级别的模型整天运行。

感觉很有力量，直到我遇到速率限制，最后被锁定等待配额 (Quota) 刷新。此时你不在构建任何东西。你只是在等待。

强大的模型在作用域明确时效果最好。把它们固定到特定的代理并在你真正需要它们时调用。不要把它们留在默认协调器循环中为日常工作消耗你的配额。

---

## 还不要买硬件

围绕购买 Mac mini 或 Mac Studio 只是为了运行 OpenClaw 有很多炒作。我强烈建议早期不要这样做。

不是每个人都有 $600 来投入这个工具，即使有，通常也是第一步做的错误决定。关于 OpenClaw 的害怕错过 (FOMO) 是真实的。很容易感到你需要立即拥有专用硬件。

先学会你的工作流。学会你的成本。弄清你的故障模式。如果我在买东西前做了这些，我会省很多钱。

---

## 本地模型的现实

本地模型被宣传为一切问题的解决方案。除非你已经有很好的硬件，数学关系很少能算出来。

一台 512 GB 统一内存和 2 TB 存储的 Mac Studio 运行超过 $9,000。要现实地部署像 Kimi 2.5 这样可用性能的东西，你需要两台。大约 $18,000 的硬件。

除非你在构建一个需要这样硬件做更多事情的业务，不只是 OpenClaw，否则跳过它。

本地模型对于实验和简单任务是可以的。但我发现费力节省几分钱通常花费的时间损失和性能下降比多付一些 API 调用费用更多。

一个相关的注意：一些免费层托管选项没有好多少。例如，NVIDIA NIM 对 Kimi K2.5 的免费层经常有 150+ 个请求在队列中。这种延迟让它对于需要秒级响应的代理工作流不可用，而不是分钟级。"免费"并不总是意味着"可用"。

## 炒作问题

这部分值得说。

现在关于 OpenClaw 有很多炒作。炫目演示、YouTube 视频承诺它会替代你做的所有事情，每个社交平台上的"这改变一切"能量。我看过人们花在配置 OpenClaw 上的时间比他们想用 OpenClaw 帮助做的工作还多。

我会鼓励人们抵抗 FOMO 并忽略大部分 YouTube 内容。很多是为了点击率优化的，而不是对真正重要的无聊星期二下午使用。

OpenClaw 在你停止期待魔法和开始期待一个需要调整的工具时变得有用。

## 便宜的模型实际上很好

对我来说一个更大的思维转变是意识到当正确使用时，一些模型有多便宜。

心跳 (Heartbeat) 经常运行但做简单检查。没有理由为后台管道消耗高级模型。我看过成千上万的心跳令牌 (Token) 在便宜模型上花费不到一分钱。

对于特定的模型推荐和成本数学，见 [`examples/config-example-guide.md`](examples/config-example-guide.md#heartbeat-model-heartbeatmodel)。

并发限制也对成本控制很重要：

```json
"maxConcurrent": 4,
"subagents": {
  "maxConcurrent": 8
}
```

这些限制防止一个坏任务级联到重试和成本失控。

## 一个实用的循环心跳模式

不是为不同的定期检查运行单独的 cron 任务，我使用一个单一的心跳，根据每个检查有多逾期轮流进行检查。

想法很简单。每个检查有一个节奏（应该运行多频繁）、可选的时间窗口（允许运行的时候）和最后一次运行时间的记录。在每个心跳 tick 上，系统运行最逾期的检查。

这批处理后台工作，保持成本平坦，避免"一切同时触发"问题。

所有心跳检查运行在非常便宜的模型上。如果检查发现需要工作的东西，它生成 (Spawning) 适当的代理而不是尝试内联做。

对于完整的实现模式和提示词模板，见 [`examples/heartbeat-example.md`](examples/heartbeat-example.md)。

## 使内存明确

我看到的大多数内存抱怨来自假设内存是自动的。它不是，默认行为如果你不配置就很混乱。

我使内存明确且便宜。我为搜索使用便宜的嵌入（`text-embedding-3-small`），基于缓存 TTL 修剪上下文（6 小时），并设置压缩在会话达到 40k Token 时自动将其刷新到每日内存文件。

这一个改变消除了大多数"为什么它忘记了那个"时刻。在我设置这个前，我不断地失去上下文并责怪模型，当它真的是一个配置问题时。

对于特定的配置设置和解释，见 [`examples/config-example-guide.md`](examples/config-example-guide.md)。

## 技能：先构建你自己的

我对第三方技能很谨慎。

我用自己构建的技能有更好的运气，并把社区技能当作灵感而不是即插即用。一个写得很差或恶意的技能能造成真实问题，当某事在凌晨 2 点破裂时调试别人的抽象很痛苦。

我也在内存中设置基本规则，比如永远不要暴露秘密或 API 密钥。不是万无一失的，但它帮助作为一个守护栏。

### 要求机器人构建或优化技能

对我帮助的一件事是变得更有纪律关于我要求机器人创建或重构技能的方式。模糊的指示每次都产生膨胀的、Token 饥渴的技能。

我使用的结构遵循来自 [https://agentskills.io](https://agentskills.io/) 的 AgentSkills 规范。我不隶属于它，但遵循那个模型使技能更容易维护和更便宜运行。

对于详细的提示词模板和例子，见 [`examples/skill-builder-prompt.md`](examples/skill-builder-prompt.md)。

关键是给机器人关于行数和结构的硬约束，所以它不会生成 2,000 行技能文件，吃掉你一半的上下文窗口。

## 使用 Todoist 进行任务可见性

早期，OpenClaw 感觉像一个黑盒。我看不出它在做什么，完成了什么，或卡住了什么。日志还不够。

我通过接线 Todoist 作为任务状态的真实来源修复了这个。当工作开始时任务被创建，当状态改变时更新，当需要人工干预时分配给我，当完成时关闭。如果某事失败，它留下对任务的评论而不是永远重试。

一个轻量级的心跳协调开放的、进行中的和看起来停滞的。它不是复杂的，但我能瞥一眼 Todoist 并确切知道事情进展如何而不需要挖掘日志。

对于构建你自己的任务追踪系统的提示词模板，见 [`examples/task-tracking-prompt.md`](examples/task-tracking-prompt.md)。

## 在 VPS 上运行

如果你想在 VPS 上运行 OpenClaw，你不需要一个大机器。一个 Hetzner CX23 就足够了。

我强烈推荐在你的本地机器和 VPS 都上 Tailscale。在 VPS 上用 `--ssh=true` 标志安装它，你可以直接通过 Tailscale 登录。然后在 Hetzner 防火墙中完全阻止 22 端口。

我阻止所有入站流量并通过 Tailscale 访问一切。简单的设置，更少的担心。

对于完整的 VPS 设置过程、安全加固和验证工作流，见 [`examples/vps-setup.md`](examples/vps-setup.md)。

## 这每个月花我多少钱

我不为所有事都通过 API 支付。

我使用两个编码订阅，每个大约 $20。在顶部，API 使用运行每月大约 $5-$10，在 OpenRouter 和 OpenAI 之间分割。

大多数月份我降落在大约 $45-$50 总计。

## 你的数字会不同

如果你让代理持续运行、允许无限制重试或通过高级模型路由所有事，成本会上升。我看过人们通过让事情无上限在一个周末达到 $200+。

如果你划分模型范围、上限并发和在便宜模型上保持后台工作，成本快速平坦化。

## 关于 Anthropic 禁止

**重要更新：** Anthropic 已正式声明使用他们的**订阅计划**用于 OpenClaw 或任何在他们生态系统外的使用携带非常高的账户禁止风险。这不适用于 API 使用——你可以直接使用 Anthropic API 而没有相同的禁止风险。

区别很重要：订阅计划（如 Claude Pro）在 Anthropic 生态系统内的个人使用。通过 OpenClaw 为自动化使用它们违反他们的条款。API 密钥是为程序化使用而设计的。

我的推荐：不要为 OpenClaw 使用 Anthropic **订阅计划**。如果你想要 Claude 模型，直接使用 API 或通过 OpenRouter 路由。

我已经更新我自己的设置以避免为 OpenClaw 使用直接 Anthropic 订阅。我配置中的回退链反映了这个。

---

## 在进行 24/7 前使事情稳定

我不从永远在线模式开始。

我先使事情稳定，通常在本地 VM 或容器中。我观察行为和成本几天。只有在事情可预测后，我让它无人看管地运行更长的时间。

在你理解它的故障模式前让一个代理无人监督地运行是如何你醒来看到 $300 API 账单和 Todoist 充满垃圾。

---

## 最终想法

你不需要昂贵的硬件或昂贵的订阅来使 OpenClaw 有用。你需要的是对配置有意、保持对发生什么的可见性和抵抗在理解基础之前过度工程的冲动。

如果这节省你一些时间或挫折，它就做了它的工作。
